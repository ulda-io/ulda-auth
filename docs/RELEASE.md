# Подготовка ulda-auth 1.0

Подготовлен **ulda-auth@1.0.0**, ещё не опубликован. GitHub: https://github.com/ulda-io/ulda-auth.
Номер без rc предназначен для стабильного выпуска; сам номер не подтверждает безопасность.

## Состав

SDK написан на JavaScript. types/index.d.ts описывает его API для редакторов и TypeScript,
но не является исполняемой реализацией. Ядро ulda-core 1.0.1, socket.io-client 4.8.1 и
socket.io-parser 4.2.7 — закреплённые npm-зависимости. Компилятор TypeScript используется
только для проверки деклараций при разработке и не устанавливается как зависимость SDK.

В npm-архив входят 29 файлов: ESM-модули, декларации, готовый browser ESM, лицензии и
документация пользователя. Тесты, CI и инструменты выпуска остаются в репозитории.
Архивы старого ядра, рабочие дневники, внутренние отчёты и сайт-стенд не входят в него.
Git-история начинается заново с одного начального коммита; старый проект хранится отдельно.

Обычный ESM использует зависимости npm, browser bundle включает их вместе с лицензиями.
Нет postinstall. Lockfile служит воспроизводимости разработки; чистая установка отдельно
проверяет разрешение транзитивных зависимостей у потребителя.

## Проверки

~~~powershell
npm ci --ignore-scripts
npm run release:check
npm run test:package -- http://127.0.0.1:3000
npm run test:browser
npm run test:publish
~~~

release:check включает сканирование текущих файлов и всех локальных объектов Git,
тесты с безопасным reporter, TypeScript, сборку, bundle round trip, чистую установку
и dry-run публикации. Артефакт и receipts с SHA-256 лежат в .local/release вне Git.
Публикация должна использовать эти проверенные байты, а не произвольную новую сборку.

Проверяются точный состав пакета и ссылки документов, публичные exports, два клиента,
Changed, X/S, recovery и удаление. Browser ESM сначала выполняется в Node/Web Crypto.
Отдельный test:browser запускает установленные Chrome/Edge с новыми headless-профилями.

Для проверки с основным сервером явно задайте loopback endpoint без credentials.
Сценарий создаёт и удаляет собственные синтетические ресурсы. Recovery, сохраняющий
старый ресурс, при этой проверке выполняется только на временном fixture.
Это короткие функциональные проверки, не полная матрица отказов или нагрузки.

test:publish сверяет архив с receipt чистой установки и package.json. Вызов npm publish
внутри него всегда содержит --dry-run --ignore-scripts; режима реальной отправки нет,
дополнительные аргументы отклоняются. Сырые сообщения дочернего процесса не печатаются.
Успех dry-run не подтверждает npm-вход, владение именем или права на публикацию.

## Безопасность тестов и границы приёмки

Тесты используют только синтетические данные и временные серверы. Reporter скрывает
произвольные сообщения, исключения и значения assertion. Проверки архивов ограничивают
распакованный объём и вложенность, неизвестные формы отклоняются. Исключения сканера
привязаны к конкретным фиктивным паролям и отрицательному URL-примеру. Сканер эвристический.

Код прошёл регрессии гонок, целостности, протокола и жизненного цикла секретов; исходная
связка проверялась с основным ULDA Server/PostgreSQL и в Chrome/Edge. Результат отдельного
прогона подтверждается receipt конкретного архива. ИИ-обзор не заменяет независимый
человеческий аудит. Такой аудит и полная согласованная браузерная/нагрузочная матрица
не завершены. Нагрузочные цифры старого стенда не выдаются за свойства этого пакета.

Node >=22, ESM/ES2022, secure-context Web Crypto/WebSocket — технические требования.
CI подготовлен для Node 22/24 × Windows/Linux; удалённый прогон выполняется после push.

## Выпуск

В package.json снят private и заданы repository, registry, public access и tag latest.
Это только подготовка. Для публикации нужны GitHub-репозиторий, проверка CI, npm-вход
и права на имя. Порядок сопровождающего находится в docs/PUBLISHING.md репозитория.
Проверенный tarball публикуется отдельным явным действием.

GitHub Private vulnerability reporting следует включить; до проверки его доступности
приватный канал — mark@shaposhnik.ch. Правообладатели подтверждают лицензионный текст.
Согласованные границы UNKNOWN_OUTCOME, orphan после Create, доверенный снимок после
offline, Changed.deleted и явное восстановление описаны в SECURITY и API.

Источники: [npm publish](https://docs.npmjs.com/cli/v11/commands/npm-publish/),
[SemVer](https://semver.org/).
